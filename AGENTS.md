# AGENTS.md

## Overview
Taxi dispatch platform: a FastAPI + MongoDB (motor) backend and a React SPA frontend that builds five apps from one codebase: **Terminal** (central/dispatch, real-time Leaflet map), **Operador** (driver), **Pasajero** (passenger), **Socio/Dueño** (fleet owner) and the public **Landing** (`taxihub.cloud`). Android apps are packaged with Capacitor. Dark theme. Spanish UI strings throughout — keep user-facing text in Spanish.

Production (`https://taxihub.cloud`) currently runs as a **demo**: a simulated fleet (34 drivers, GPS patrol over real Palenque streets) is seeded at startup. Keep the simulation working unless the user says otherwise.

## Layout
- `backend/server.py` (~3k lines) — app setup, storage helpers, auth dependencies (`require_*`), Pydantic models, `ConnectionManager`, the GPS pipeline + geofence, the dispatch engine (`_buscar_candidatos`, `_asignar_atomicamente`, autodespacho, cascade/retry loops), routing/geo, `_migraciones`, startup and the router wiring. Route prefix `/api`.
- `backend/*_module.py` — one router per area, each a factory (`build_router(...)`, or `build(...)` returning a namespace when `server.py` must re-export functions) that receives its dependencies as keyword arguments and `db=_db_proxy` (resolves `server.db` on every access so the tests' monkeypatch keeps working): `auth`, `operadores`, `turnos` (shifts + fuel), `clientes`, `catalogos` (vehicle types, vehicles, routes, colonias, tarifas), `servicios`, `reportes` (+ `/files`), `chat`, `dueno`, `sitio` (photos, logos, site config), `dev`, `whatsapp`, `websockets`, `simulacion` (seed + GPS patrol; data in `simulacion_datos.py`), plus `mantenimiento`, `socios_extra`, `terminal_consulta`. Module routers are included after `api_router`, so route order matters: keep a parametrized path (`/x/{id}`) in the same router as, and after, the literal paths it could shadow; `dueno_module` is included before `socios_extra_module` because both define `/dueno/notificaciones` and `/dueno/conductores`. Code that reads a module global the tests monkeypatch (`ROUTING_PROVIDER_URL`) stays in `server.py`.
- Mongo collections in use include `operadores`, `vehiculos`, `tipos_vehiculo`, `clientes`, `servicios`, `rutas`, `colonias`, `tarifas_predefinidas`, `turnos`, `combustible_cargas`, `reportes_objetos`, `mensajes_chat`, `wa_conversaciones`, `usuarios_terminal`, `usuarios_dueno`, `sitios`, `config`, `archivos`, plus owner/maintenance collections.
- `wa-bridge/` — Node 22 + Baileys WhatsApp bridge (one linked-device session per sitio, own container `taxihub-wa-bridge`, volume `taxihub_wa_sesiones`); see its README. `backend/whatsapp_module.py` talks to it; demo sitios (`default`, `sitio_pakalna`) stay simulated so nobody links a real WhatsApp to the public demo accounts.
- `backend/app/db.py` + `migrations/` — Postgres/SQLAlchemy scaffolding that is **not used** by the running app yet.
- `frontend/` — Create React App **via CRACO** (`craco start/build/test`). Path alias `@` → `src`. Tailwind + shadcn/ui + Leaflet. App selection in `src/App.js` (`REACT_APP_APP_MODE`, `?app=`, native platform).
- `frontend/public/assets/drivers/` — demo driver portraits (Pexels stock, see `CREDITS.md`), assigned by gender in `simulacion_datos.py` (`FOTOS_DEMO_HOMBRES` / `FOTOS_DEMO_MUJERES`, re-exported by `server.py`). Never use photos of public figures.
- `memory/PRD.md` — feature/phase history; `docs/` — per-phase design docs and `DEPLOYMENT.md`.
- `CLAUDE_HANDOFF.md` (root, gitignored) — VPS access and production credentials. **The GitHub repo is public**: never commit hosts, keys, passwords or that file.

## Backend
- Env: `server.py` loads `backend/.env` (gitignored). `MONGO_URL` (`memory` = in-memory mongomock), `DB_NAME`, `JWT_SECRET` (mandatory and non-default when `ENV=production`, otherwise startup fails), `CORS_ORIGINS`, `DEV_USER`, `DEV_PASSWORD`, `WA_WEBHOOK_TOKEN` (shared secret with the WhatsApp bridge, both directions: bridge → `/api/wa/incoming` and `/api/wa/webhook`, backend → bridge), `WA_BRIDGE_URL` (default `http://127.0.0.1:3099`), `WA_PUENTE_EN_DEMO` (`1` lets demo sitios use the real bridge — testing only), `SIMULACION_DEMO` (default `1`), `DESPACHO_PRIORIDAD_USUARIO` (default `op1`; empty disables the demo priority driver).
- Run: `uvicorn server:app --reload` (from `backend/`). The frontend dev env (`frontend/.env.development`) expects the API on `127.0.0.1:8001`.
- Auth: JWT scopes `operador`, `terminal`, `pasajero`, `dueno`, `dev`; every token carries `sitio_id` (tenant). Dev panel at `/dev` validates against `DEV_USER`/`DEV_PASSWORD`.
- Dispatch: passenger requests are auto-offered to one driver at a time (`_autodespachar_servicio_pasajero`), cascading after `config.oferta_duracion_seg`; pending passenger trips are retried every 10 s and expire after `config.pendiente_max_minutos`. Assignment reserves the driver atomically (`_asignar_atomicamente`). Candidates need fresh GPS (`config.gps_stale_seconds`) or a live operator WebSocket.
- Lint/format deps installed (`black`, `isort`, `flake8`, `mypy`) but there is **no** configured command/script.
- Real-time via the in-file `ConnectionManager` (terminal broadcast per sitio + per-operador/pasajero/dueño websockets). Background loops (cascade, GPS patrol) run in-process: run a **single** uvicorn worker.
- File uploads are stored on local disk in `backend/uploads/` (`put_object`/`get_object`), served via `GET /api/files/{path}`.

## Frontend
- `frontend/src/lib/api.js` — API client. `BACKEND_URL` from `REACT_APP_BACKEND_URL` (or `localStorage.th_backend_url`); JWT per app in localStorage (`op_token`, `pas_token`, …). WS base derived from the same URL.
- Theme/palette via `data-theme` in localStorage; app root is forced `dark`.
- Brand identity (`docs/DESIGN.md`): yellow `#FFE600` (hover `#FFB800`, gradient to `#FF9900`) on blue-black surfaces `#050B12` (background and ink on yellow) / `#0A121D` / `#0F1926`, soft white text `#EDF2F8`, blue-gray muted `#93A4B8`. Green `#22C55E` only for positive operational states (Disponible, En línea, GPS OK, completado); red/orange/purple for the other states (SSOT `design/status.js`). Logo = `BrandMark` in `Brand.jsx`; subtitle "CENTRAL Y DESPACHO SATELITAL". Demo sitios are seeded with `tema: "amarillo"` / `color_primario: "#FFE600"` (a sitio's `color_primario` overrides `--brand` in the apps); `_migraciones` step 8 moves the old cyan/emerald defaults. 3D controls (`th-btn-y`, `th-3d`, `chip`, `th-seg`, `th-live`, `th-gauge`) live at the end of `design/tokens.css`.
- Palette selector (`ThemeSwitcher`, `AjustesApariencia`): `applyTheme(id, { porUsuario: true })` clears the inline `--brand` that `applySitioBranding` writes from the sitio's `color_primario` and sets `app_theme_user_override`, so the manual choice wins. App code uses Tailwind `brand` tokens (`bg-brand`, `text-brand`, `border-brand/40`, `brand-strong`) instead of hard-coded `#FFE600` so it follows the palette; the landing keeps its fixed yellow. The app root is `<div class="App dark">`: the shadcn `.dark` block in `index.css` is overridden at the end of `tokens.css`.
- Mode button (`ModeToggle`): yellow sun in night mode, moon in day mode; accepts `claro`/`onToggle` for apps with their own mode state (driver `driver_mode`, passenger `passenger_mode`).
- Terminal map: `FiltroUnidadesMapa` (button "Unidades en mapa", opens upward) filters map markers by status (`th_estados_mapa` in localStorage; the fleet list is not filtered). Route filter is a popover button on the right of the `FleetPanel` header. Popovers over the Terminal need `z-[1200]` (panels sit at z 400–700). Unit card (`MissionCard`) is rendered at `zoom: 1.3` in a 370 px panel; the map popup sizes in `SmoothTaxiMarker` are the base design × 1.3. 3D vehicle markers: `taxiStateAssetIcon` + `.th-taxi3d-*` classes in `tokens.css` (relief filter on a non-rotating wrapper, sheen masked with the asset).
- Socio panel: `.dueno-shell` with `--ui-alpha` (Ajustes de apariencia → Transparencia de paneles, `dueno_ui_alpha`); zone-focus bars `th-barra3d`, badges `th-insignia3d`.
- Terminal UI zoom: CSS `zoom` on `<html>` (default 80%, `localStorage.th_ui_zoom`, 70–100% in the display-settings popover), reset when leaving the Terminal. The shell is sized in px (`innerWidth / zoom`) with `maxWidth`/`maxHeight: none`, because `100vw`/`100vh` don't fill the window under zoom.
- Browser demo for recording videos: `components/DevicePreviewWrapper.jsx` (web only, not native). Top bar tabs Modo Dual / App Operador / App Pasajero (one app only) plus Centrar / Pantalla completa / Pop-up; `?dual=1` forces dual. Header with the logo, title and product text; feature columns at ≥ 1280 px wide; fits 1920×1080 without scrolling.
- `pasApi`'s 401 handler only clears and reloads when a `pas_token` exists; reloading without a session caused an infinite reload loop.
- Driver map: `components/maps/DriverMap3D.jsx` (MapLibre GL: OpenFreeMap dark style + 3D buildings, AWS Terrarium relief on capable devices, camera follows the taxi). Used when WebGL exists and `driver_map_3d` isn't `"0"`; otherwise the Leaflet map. The taxi image faces east (rotation = heading − 90°); `rumboFiable` in `OperadorApp.jsx` only trusts GPS heading when moving (≥ 1.5 m/s or ≥ 8 m displacement).
- Landing (`pages/LandingPage.jsx`, `components/landing/`): sections Hero → Capacidades (`#funciones`) → Explorador (`#producto`) → ComoFunciona → Beneficios → Pricing (`#precio`) → FAQ → Contact (`#contacto`). Motion system in `landing/motion.jsx` (durations/curves mirrored as CSS vars in `landing.css`; respect `prefers-reduced-motion`). Interactive demo in `landing/demo/`: `flota.js` is a synthetic fleet on real Palenque streets (`pistas.js`, generated from `backend/simulacion_datos.py`) with a dispatch state machine that mirrors the real one (offer to one driver, cascade, assignment, trip); it never calls the API. `MapaDemo.jsx` = MapLibre + OpenFreeMap dark style repainted to the palette, `cooperativeGestures` (the wheel scrolls the page; Ctrl/⌘ + wheel or the buttons zoom). Never put `position` or a `transform` animation on a MapLibre marker root element (it breaks positioning; animate `translate`/`scale` or children). Real captures in `public/landing/` (`terminal|operador|socio.*`, `taxihub-demo.*`, `og-taxihub.jpg`); hotspot coordinates in `Explorador.jsx` are percentages of those images. Keep claims verifiable (no invented metrics).
- E2E testability: interactive elements get `data-testid` values, centralized in `frontend/src/constants/testIds/` (one file per feature, re-exported from `index.js`). Value convention is kebab-case `<feature>-<element>`. Add new test IDs there when adding UI; do not inline raw strings in JSX (many legacy inline ones remain).
- Native voice/alerts/notifications in the APK: `TaxiHubNativePlugin` (Capacitor plugin, registered in `MainActivity` before `super.onCreate`) wraps `TaxiHubNativeBridge` (Android TextToSpeech, ringtone + vibration, high-priority notification channel). Web code reaches it through `puenteNativo()` in `lib/voz.js`; `window.TaxiHubNative` (addJavascriptInterface) only appears after a page reload, so never rely on it alone. The manifest's `<queries>` for `TTS_SERVICE` is required on Android 11+ or TextToSpeech can't find the engine. The Android WebView has no `speechSynthesis`, `SpeechRecognition` or `Notification` API.
- Driver WebSocket heartbeat: the app sends `"ping"` every 25 s and the server answers `{"type":"pong"}`; no pong for 70 s → reconnect. On resume (`visibilitychange` / Capacitor `resume`) it reconnects if needed and re-checks `/servicios/mis-activos` for a pending offer.
- Capacitor 8 everywhere (`core`, `android`, `cli` and the official plugins): keep them on the same major when upgrading. `scripts/build_all_apks.py` builds the three APKs (driver, passenger, owner) with `cap sync` + `gradlew assembleDebug -PappId=…`.

## Testing (important)
- **Do not modify `backend/pytest.ini` `addopts`** — keep exactly `-n 2 --dist loadscope` (pytest-xdist is a required plugin). Serial run = `-n 0` (NOT `-p no:xdist`, which errors).
- Run from `backend/`: `python -m pytest -q`. With freshly installed packages pytest may wrongly report the required plugins as missing; add `-o required_plugins=` (do not edit the ini).
- Suites live in `tests/` (backend, mongomock, ~100 tests); generated suites appear under `test_reports/`. A `-n`/`--dist` custom option in your own test code will collide with xdist's — rename it.
- `test_result.md` contains the required agent testing protocol. Preserve the `#===`-delimited block verbatim and update the YAML data (status_history, test_plan, needs_retesting) per that protocol; it's the handoff channel for the testing agent.

## Deploy
- Use `scripts/deploy_vps.sh` (see `docs/DEPLOYMENT.md`): tests → `git archive HEAD` → rebuild and recreate only `taxihub-backend`, `taxihub-frontend` and (when the VPS `.env` has `WA_WEBHOOK_TOKEN`) `taxihub-wa-bridge`. Never delete the `taxihub_wa_sesiones` volume: it holds the centrals' linked WhatsApp sessions. Run `--revisar` (read-only) first. Do not `docker cp` into containers.
- `/usr/share/nginx/html/downloads/` in `taxihub-frontend` holds the APKs and the Windows installer (volume `taxihub_downloads`): never delete or overwrite it.
- The VPS hosts other projects (Caddy `nexium-caddy`, other apps): never restart or modify containers that are not `taxihub-*`. Confirm every production action with the user.

## Package manager
- Frontend uses **yarn** (packageManager pinned yarn@1.22.22); use `yarn` not npm for installs. Backend uses pip with `backend/requirements.txt`.
